# 全局核心规则与开发红线 (Trae Custom Instructions)

这是我们交互过程中沉淀的所有核心记忆规则。通过将此文件固化在代码库中，即使你在不同电脑上克隆或拉取代码，所有 SOLO 代理和助手也会**自动优先遵循**这些规范。

## 🔴 绝对红线 (User Rules)
1. **全自动闭环与免打扰**：接到任务后必须全自动拆解TODO并连续执行闭环，直接交付最终结果。中途绝不允许停下来打扰用户或要求用户做手动操作。禁止只给教程，缺环境需自动寻找和配置。
2. **禁止阻塞死循环**：禁止以阻塞方式（blocking:true）运行长驻或死循环脚本。必须使用 `RunCommand{blocking:false}` 放后台并通过 `CheckCommandStatus` 监测，严禁 `Start-Process -NoNewWindow` 导致终端无限刷屏假死。
3. **版本号强制递增**：每次完成任何代码修改后，在执行双端同步前，必须全自动递增项目的全局版本号（如 main.go、index.html），并告知用户。
4. **强制双端同步与启动模拟器**：每次修改代码后必须全自动执行编译和部署（如 fast-deploy.ps1），并在本地重新编译启动 Collector 和所有对应的本地模拟器程序，若失败必须给用户明确的报错提示。
5. **严禁交互式密码**：在执行脚本、SSH登录或部署命令时，强制使用非交互式方法（如 sshpass、plink -pw 或从 .env 读取），绝对禁止弹出密码框打断用户。
6. **终端前台显示**：执行任何命令或持续监控任务时，禁止让终端在后台默默运行，必须默认打开并显示到前台对用户可见。
7. **硬件配置先读后写**：在处理底层硬件协议、修改任何硬件级配置（如Cmd指令、Modbus寄存器）时，必须先通过“查询（Read）”操作验证地址和字节序的正确性，严禁盲写。
8. **严格零警告**：执行命令后必须主动随时监测编译和运行输出，通过代码修改、环境配置等方式，消除所有警告和错误。

## 🟡 开发与环境规范 (Dev & Env)
1. **国内源优先**：凡是可以使用国内镜像源的（如 Rust/Cargo, npm, pip 等），必须优先配置并切换为国内源再执行下载，防止网络阻塞。
2. **禁用裸curl**：PowerShell 环境中测试接口时，严禁直接使用裸 `curl` 命令（会被别名解析导致交互卡死）。必须使用 `curl.exe` 或 `Invoke-RestMethod`。
3. **Git 自动读取私钥**：在执行 Git 推送/拉取前，必须主动读取 `.env` 文件中的 `GITHUB_KEY_DIR` 变量进行免密认证。

## 🔵 业务与架构规则 (Project Rules)
1. **拥抱国际标准协议**：后续架构重构必须优先采用 SiLA 2 或 OPC-UA LADS 标准，禁止随意创建私有 API，建立统一数字孪生核心模型。
2. **测试机与模拟器**：后续所有开发测试必须全部使用测试机（真实硬件/边缘工控机）和真实数据，禁止使用本机模拟（除非明确要求）。只直连色谱仪主板，默认固定 TCP 25001/8000、HTTP 8080。
3. **核心数据结构兼容**：后端核心数据结构（如分析方法、峰组分等）必须严格沿用老软件（C# 遗留项目）定义，保证底层逻辑兼容性。
4. **多硬件自适应 (HAL)**：散件模式下循环周期由前端 `/api/control/cycle` 发送，后端 `engine_scheduler` 自主触发；遗留模式根据活跃连接动态绑定 DeviceID，确保多协议兼容。
5. **图表绘制基线**：Canvas 波形必须保留 0 基线，确保坐标轴方向正确（Y轴反转），高度必须自适应且上下保留 10%-20% 视觉余地。
6. **前端图片生成**：禁用前端直接调用动态图片生成接口。预览使用静态真实网图，真实的 AI 绘图需求必须由后端程序调用，下载本地后再返回 URL。
7. **日志过滤**：必须主动过滤主板频繁发送的底层调试（DEBUG）日志，仅保留具备业务价值的日志，并在前端提供配置开关。
8. **TCD 本地配置**：本地进行 TCD 模拟时必须使用 COM10 和 COM11 作为一对虚拟串口。同时需配置 `$env:EDGE_ALLOW_CONTROL="1"` 启用 UI 控制按钮。
