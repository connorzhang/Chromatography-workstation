# 前端界面需求分析与 PRD 重构设计 (在线监测)

根据 `src/edge/docs/` 目录下的参考截图，重构后的 Go 边缘节点 Web 界面将聚焦于“在线监测”这一特定场景，摒弃旧版本 (C#) 中不必要的多窗口、多弹窗交互，转而采用现代单页应用 (SPA) 架构。

## 0. 核心架构原则 (非常重要)

1. **绝对的后端主导 (Backend-Driven)**:
   - **所有业务逻辑必须在 Go 后端独立实现**。包括循环进样控制、采集时序、积分计算、硬件反控下发、数据持久化存储等。
   - **完全脱机运行能力**：即使前端界面完全没有被打开，或者前端突然断开连接，Go 边缘节点必须能够稳定、持续地完成数据采集、计算和云端上报（如 MQTT）。
   - 前端仅仅是一个“遥控器”和“监视器”，只负责数据呈现和用户配置指令的下发。
2. **状态与配置持久化**:
   - 后端负责维护系统的**单一事实来源 (Single Source of Truth)**。所有的仪器方法、校准曲线、系统设置必须持久化在后端（如 SQLite 或 JSON 配置文件）。
   - 前端打开时，向后端请求当前全量状态并初始化渲染；前端修改配置时，仅向后端发送更新请求，不应在前端本地存储核心业务状态。
3. **极简轻量化技术栈 (Vanilla Stack)**:
   - 为保持边缘节点的高效、轻量和部署极简，**坚决不引入庞大的第三方框架**（如 React, Vue, Angular）和复杂的 Node.js 构建工具链 (Webpack/Vite)。
   - **技术栈限定**：原生 HTML5 + 原生 JavaScript (ES6+ Module) + 原生 CSS3。
   - 通过原生 JS 模块化 (`import`/`export`) 和 DOM 操作实现组件化和路由切换。

---## 1. 整体布局结构
采用典型的**顶层导航栏 + 主体内容区**的布局结构，整体风格简洁、数据导向，适合工业级监测屏和触控屏操作。

- **顶栏 (Header)**:
  - 左侧: 系统标题 "在线监测"。
  - 右侧/中部: 提供 6 个主要功能模块的切换标签（Tab），分别是：
    1. **主界面** (监控大屏，突出实时浓度与状态)
    2. **谱图** (实时信号与波形展示)
    3. **仪器方法** (校准曲线及积分参数配置)
    4. **谱图处理** (历史谱图回顾与离线处理)
    5. **记录报表** (历史监测数据查询与导出)
    6. **系统设置** (硬件参数、通信与系统级配置)

## 2. 各模块界面拆解与组件规划

### 2.1 主界面 (Dashboard)
**核心诉求**：让操作员远距离一眼看清当前浓度和设备运行状态。
- **左侧数据区 (浓度展示)**:
  - 三个大号数据卡片（Block），从上到下依次展示核心指标（如：总烃、甲烷、非甲烷总烃）。
  - 每个卡片采用蓝色高亮背景，左侧显示组分名，右侧大号字体显示实时计算出的浓度数值。
- **底部状态栏**:
  - 显示实时运行时间 (min) 与当前信号值 (pA)。
  - 展示当前状态信息模块：运行次数、单位 (mg/m³)、进样状态。
  - 右下角展示当前系统日期和时间 (电子表样式大字体)。
- **右侧预留区**: 
  - 根据截图目前为空白，可预留用于展示仪器整体报警状态、气路简图或最新的一条系统日志。
  - 中央底部有一个显眼的“火焰”图标，用于指示 FID 检测器的点火状态。

### 2.2 谱图 (Chromatogram Live)
**核心诉求**：提供类似示波器的实时波形监控。
- **顶部控制栏**:
  - 通道切换与状态展示（如“通道1结束”）。
  - 进样类型选择（单选框）：正常进样、零气反标、标气反标。
  - 坐标轴控制输入框：下限(Y)、上限(Y)、采集时间(X)、满屏时间(X)。
- **中部波形区**:
  - 基于 Canvas/SVG 的高频实时色谱图，显示 X 轴 (时间 min) 和 Y 轴 (信号 pA)。
  - 实时绘制出峰的组分名称和保留时间标注（如“总烃 0.1017”，“甲烷 0.5892”）。
- **右侧数据区**:
  - 上半部：展示当次分析得出的组分浓度列表（名称、含量 mg/m³）。
  - 下半部：仪器物理参数实时监控面板。
    - **实测气路面板**: 载气、氢气、空气实时压力/流量。
    - **实测温度面板**: 柱箱、阀温、检测器、进样口实时温度。

### 2.3 仪器方法 (Method & Calibration)
**核心诉求**：设置组分积分参数与校准曲线。
- **左侧控制区**:
  - 三个子标签页：组份编辑、校准曲线、自动校准。
  - **组份编辑列表**: 表格形式，包含名称、保留时间、窗宽、面积、标气浓度等列。
  - **底部控制**: 校正级别选择 (+/-)、偏移设置，以及方法文件的管理（新建、加载、保存并应用、删除）。
- **右侧波形与结果区**:
  - 顶部按钮：打开谱图、应用到方法、下拉框选择组分。
  - 中部：用于展示标气谱图的静态波形组件。
  - 底部：峰识别结果列表（序号、保留时间、面积、高度、开始时间、结束时间）。

### 2.4 谱图处理 (Offline Processing)
**核心诉求**：查看历史谱图，重新手动/自动积分。
- **顶部操作栏**:
  - 提供一系列文件和显示控制按钮：打开谱图、关闭谱图、保存 xml、框选放大、重叠打开谱图、删除谱图及数据、重置、满屏。
- **中部波形区**:
  - 静态色谱图展示区，支持交互式鼠标缩放、拖拽。
- **底部数据区**:
  - 包含两个子标签：结果、总结。
  - 结果表格：展示重算后的详细峰数据（组份名称、保留时间、面积、高度、开始结束时间、浓度等）。

### 2.5 记录报表 (History Report)
**核心诉求**：历史浓度数据的查询与导出。
- **主体表格**:
  - 展示历史进样的批次结果，列包含：时间、总烃、甲烷、非甲烷总烃等。
- **底部筛选与操作**:
  - 时间范围选择器：起始时间 (YYYY/MM/DD HH:mm:ss) 至 结束时间。
  - 导出按钮：导出数据 (CSV/Excel)。
  - 删除操作：提供如“NMHC 删除选中数据”等数据管理按钮。

### 2.6 系统设置 (System Settings)
**核心诉求**：硬件配置及底层参数设定。
- **顶部分类标签**:
  - 仪器参数1、仪器参数2、上传参数、log、数采仪。
- **外部事件模块 (表格)**:
  - 矩阵式设置 8 个外部事件在不同时间点的吸合与释放时间。
- **气路参数模块 (表单组)**:
  - 包含载气、氢气、空气、辅助气的实测值显示、设定值输入框以及对应的“设定”按钮。分为多路（如载气1、载气2）。

## 4. 下一步行动建议
1. **纯原生前端架构设计**：在 `src/edge/static/` 目录下建立原生的模块化目录结构（如 `js/components/`, `js/views/`, `css/`）。利用 `document.getElementById` 和 `classList.toggle('hidden')` 实现 6 个主 Tab 的单页切换。
2. **定义后端数据结构**：在开发任何前端功能前，先在 Go 后端定义好所有的业务结构体（如 `CalibrationMethod`, `SystemSettings`, `EventTable`），并使用 JSON 或 SQLite 完成本地持久化。
3. **接口契约先行**：明确前后端通信的 API。实时高频数据（如波形、当前浓度）继续走 SSE；配置下发和历史查询走 RESTful API (`GET /api/method`, `POST /api/method`)。
4. **后端控制逻辑重构**：将原先与 UI 耦合的循环逻辑彻底沉淀到 Go 的独立 goroutine 中，确保脱机状态下的循环进样、硬件指令下发、结果计算与入库无缝运行。
