# 变更记录

## [v0.3.27] - 2026-05-29 (MQTT上传优化)
- **MQTT 数据上传精度优化**：MQTT 上报结果（Result）中的组分浓度（Amount）强制四舍五入保留最多 3 位小数，避免过长浮点数浪费带宽。
- **MQTT 垃圾日志过滤与开关**：
  - 在前端高级设置中增加了「包含底层通信 (DEBUG) 日志」开关配置（默认关闭）。
  - MQTT 日志上传队列严格拦截 DEBUG 级别的通信报文，仅当用户显式开启配置时才上传，大幅节省遥测流量。

## [v0.3.26] - 2026-05-29 (数据对接与联调闭环)
- **HJ212-2025 VOC 谱图上传**：
  - 基于环保平台协议（5300 端口）新增谱图 XML 自动生成与异步表单上传功能。
  - 谱图曲线数据强制保留 3 位小数，大幅缩减 Payload 体积，优化传输性能。
  - 彻底修复 `finalizeSession` 与 `publishSessionResultSnapshot` 导致的数据双写与重复日志打印 BUG。
- **Modbus TCP 标准化与全量映射**：
  - 适配 TCP 网关规范，地址不匹配时严格回复标准 Exception 11 (0x0B)。
  - 完成实时数据全量映射：101 (状态)、111+ (温度)、125+ (流量)、211+ (浓度)、231+ (面积)、251+ (高度)、675+ (保留时间)、801+ (设备编码)。
  - 新增 Float32 的 `CDAB` (低字在前，高字在后) 字节序写入适配，满足上位机读取规范。
- **日志队列与业务解耦**：
  - 在 Modbus 700+ 寄存器实现日志环形队列机制，限制 15 秒更新一次。
  - 彻底过滤底层通信心跳 (DEBUG) 垃圾日志，并提供前端开关（仅同步高价值 INFO/WARN/ERROR 日志）。
- **状态同步彻底重构**：
  - “单一事实来源”重构版本号体系，全局共享 `AppVersion`，后端模板渲染拦截并注入前端 HTML，彻底消除版本不同步隐患。
  - 修复重启服务后出现幽灵“停止分析”状态的问题，将底层状态机 (active) 与日常基线探测 (Cmd 143) 彻底解耦，仅在确认收到启动指令 (Cmd 146/150) 后才激活分析态。

## [v0.3.18] - 2026-05-29 (当前联调进度)
- **底层协议修正 (GCKC Legacy)**：
  - 彻底破解并修复遗留硬件控温开关逻辑：`Cmd 16` 确认为**状态翻转 (Toggle)** 指令，废弃原以为的 `Cmd 17`。
  - 修正 `Cmd 67` 控温通道使能位掩码映射，解决进样2 (Det2) 与检测2 (Inj2) 控制反转的问题。
  - 修复温度下发 `Cmd 8` 缺失保护温度导致硬件断电降温的致命 Bug。
  - 修正 BCD 温度编码算法，确保浮点数精确放大并正确拆分高低位。
- **Modbus 温控模块扩展**：
  - 新增 Modbus 独立温控模块的 **IO 输出模式** 支持。
  - 支持向寄存器 78 配置为 IO 模式的通道（如通道5~8，对应线圈地址 36~39）下发开关量指令。
  - 在前端调试 (Debug) 页面新增独立的 "开关量输出测试 (IO 模式)" 面板。
- **前端与全栈优化**：
  - 前端设置页新增硬件“获取中/升温中 (ON)/已停止 (OFF)” 实时状态指示灯。
  - 解决后端重启后 API 状态丢失导致 404 的问题，前端强制透传 `deviceId`。
  - 同步更新相关协议文档 (`GCKC_PROTOCOL_DEVELOPER_GUIDE.md`, `GCKC_PROTOCOL_COMMAND_REFERENCE.md`, `温控模块Modbus通信协议说明.md`)。
